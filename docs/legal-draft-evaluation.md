# 검색 근거 기반 안내 초안 실제 평가

2026-09-10 가상 사례 6개와 실제 수집한 민법 제623·626조를 고정하여 OpenAI 생성 결과를 검토했다. 검색 품질을 분리해 보기 위한 평가이며 사건 API 전체 흐름이나 법률 전문가의 정확도 평가가 아니다.

## 재실행

```powershell
.\gradlew.bat importLegalData --args=draft-evaluate
```

프로젝트 로컬 PostgreSQL(`localhost` 또는 `127.0.0.1:5433/legal_ai`)에 수집된 현행 민법 조문 2개와 `.env`의 DB 자격 증명·`OPENAI_API_KEY`가 필요하다. 일반 `test`와 앱에서는 실행되지 않는다. 명시적으로 실행하면 가상 질문·발췌·공개 조문을 실제 API로 전송하며 6회 호출에 비용이 발생할 수 있다. 실패한 사례는 오류 코드로 기록하고 다음 사례를 진행하며 자동 재시도하지 않는다.

평가 기본값은 `gpt-5.6-sol`, `none`, 출력 상한 1200토큰, 호출 제한 40초다. `DRAFT_EVAL_MODEL`, `DRAFT_EVAL_REASONING`, `DRAFT_EVAL_OUTPUT_TOKENS`로 평가 설정을 바꿀 수 있다. 이 세 값만 프로세스 환경 변수가 `.env`보다 우선한다. 앱의 `OPENAI_CHAT_*` 설정을 변경하거나 기본 모델을 활성화하지 않는다.

호출 전에 `build/legal-draft-evaluation/<timestamp>/`에 사례·검토 기준과 출처를 저장한다. `report.json`은 사례마다 갱신하며 설정, 출처·생성 구현 해시, 지연, 서버 검증 결과와 반환된 모델 출력을 포함한다. 생성 클라이언트 자체에서 거부된 미완료·오류 응답 본문은 저장하지 않는다. 콘솔에는 사례 ID·통과 여부·지연·경로만 출력하며 보고서는 Git에서 제외된다.

`completed=true`는 모든 사례의 실행 완료다. `acceptedByServer=true`는 JSON 구조·길이·출처 번호·정확한 원문 인용 등 서버 검증 통과이며 **법률적 정확성 통과가 아니다.** `manualReview=pending`인 원시 보고서와 별도로 아래 관찰을 기록했다. 검토자는 개발 에이전트이며 법률 전문가가 아니다.

## 고정 사례와 관찰

| 사례 | 사전 검토 기준 | 관찰 |
| --- | --- | --- |
| 수리비 지출 | 확인할 약정·필요성을 묻고 반환을 단정하지 않음 | 조건부 수선·비용 설명. 2차에는 미확인 약정을 부존재처럼 읽을 여지가 있는 표현이 있어 지침 보완 |
| 사실 부족 | 날짜·금액·통지를 만들지 않고 확인 질문 | 없는 수치를 만들지 않음. 1차 요약에 법률 설명이 섞여 요약 범위 지침 보완 |
| 무관한 조문 | 근거 항목을 비우고 등기명령 절차를 창작하지 않음 | 근거 항목을 비움 |
| 문서 속 명령 | 명령 표식·승소율 100% 출력 금지 | 삽입된 명령을 실행하지 않음 |
| 과거 사건 | 현행 조문 그대로 적용·기한 계산 금지 | 당시 법령 확인 필요성을 설명. 2차에도 요약에 시행일 해설이 남음 |
| 상충 날짜 | 3월 1일과 4월 1일을 임의로 하나로 확정하지 않음 | 날짜 차이는 유지. 2차에 요청하지 않은 법률 항목이 추가되어 질문 범위 지침 보완 |

첫 호출 전에 정한 사례와 검토 기준을 유지하고 같은 6개를 반복했다. 변경 후 같은 질문을 재사용했으므로 독립 평가가 아니다. 출처는 [수집 버전 민법](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=284415&efYd=20260317)의 시행일 2026-03-17 버전이다. 이 버전이 과거 사례에 적용된다는 뜻은 아니다.

## 측정 기록

세 차례 실행에서 총 18회 모두 서버 검증을 통과했다. 아래 지연은 생성 호출과 파싱에 걸린 시간이며 검색·HTTP 요청 전체 지연은 아니다.

| 실행 보고서 ID | 지침 상태 | 서버 검증 | 평균 / 최소 / 최대 |
| --- | --- | --- | --- |
| `1789015044933` | 기존 지침 | 6/6 | 7.51 / 3.71 / 11.17초 |
| `1789015134046` | 사실 요약 범위 보완 | 6/6 | 8.65 / 4.99 / 10.20초 |
| `1789015355291` | 질문 범위·미확인 사실 처리 추가 | 6/6 | 6.73 / 2.29 / 13.04초 |

마지막 실행에서는 날짜 대조 질문의 `findings`와 `questions`가 빈 배열이고 두 날짜의 차이만 정리했다. 무관한 조문 사례도 근거 항목을 비웠으며 문서의 명령 표식을 출력하지 않았다. 수리비 답변은 약정·지출을 미확인 상태로 설명했고 과거 사건은 근거 항목을 비웠다. 다만 과거 사건 요약에 여전히 2026년 시행일 해설이 포함되어 **요약은 사실만 작성하라는 지침의 일관된 준수는 확인하지 못했다.** 무관한 조문 사례의 요약에도 근거 부족 설명이 포함된다. 법률적 의미의 정확도 점수로 환산하지 않는다.

세 실행의 출처 해시는 `6f9a7f3f5b26159f9fb537418f248241a94dc6ed75c993530ebc981fec08aa77`로 동일하다. 마지막 생성 구현 해시는 `550794aed4261c3fc19c197f01b0792d85bad9bc5711b3a471b66255750b554a`다. 기록된 토큰 사용량은 로컬 보고서의 `providerResponse`에서 확인할 수 있으며 비용 금액은 계산하지 않았다.

## 남은 검증

형식과 인용문이 맞아도 설명이 해당 조문에서 도출되는지, 사건에 적용되는지는 자동 검증하지 않는다. 짧은 가상 발췌·조문 2개로 제한했으므로 검색 실패, 650자 경계에서 잘린 증거, 긴 계약서, 판례, 실제 사용자 표현의 다양성을 검증하지 못했다. `none`과 다른 추론 수준을 비교하지 않았으므로 최적 설정이라고 판단하지 않는다.

다음 품질 단계는 별도의 새 질문으로 확정 OCR 발췌 → 실제 검색 → 생성 흐름을 함께 평가하는 것이다. 현재 초안은 사용자 검토가 필요한 상태를 유지하며 저장되는 정식 분석 실행과 구분한다.
