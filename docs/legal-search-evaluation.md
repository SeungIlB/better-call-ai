# 주택 임대차 검색 용어 보완 평가

검색은 법률 답변 생성 전의 근거 후보 조회다. 이번 변경은 원래 질문을 유지하면서 주택 수선·필요비·감액·보증금·묵시적 갱신에 관한 검색 용어를 추가한다. 적용 조문 번호를 하드코딩하거나 조문을 결과에 강제로 삽입하지 않는다.

## 실행과 판정

```powershell
.\gradlew.bat importLegalData --args=search-evaluate
```

명시적으로 실행하는 실제 API 평가다. 프로젝트 로컬 DB와 `.env`의 키를 사용하며 일반 `test`에서는 실행하지 않는다. 고정 가상 질문 14개마다 원문과 용어 보완문을 한 배치로 임베딩한다. 총 14회 요청·28개 입력이며 과금될 수 있다. 질문과 정답은 호출 전에 `build/legal-search-evaluation/<timestamp>/examples.json`에 기록한다. 각 질문 처리 후 보고서를 갱신하며, 외부 호출 실패 시 재시도 없이 중단한다. `completed=true`는 모든 질문 실행 완료를 뜻하며 정확도 통과를 뜻하지 않는다. 누락은 보고서의 목표 조문과 실제 결과를 비교한다.

양쪽 모두 동일한 임베딩 모델(`text-embedding-3-small`), 법령 DB, RRF 검색과 최대 8개 조각을 사용한다. 목표 법령명·조문 제목이 상위 8개 조각 중 하나에 정확히 포함되는지 검사한다. 같은 조문의 여러 조각은 중복 적중으로 계산하지 않는다. 목표 조문은 검색 관련성을 검사하기 위한 개발자 선정 항목이며 사건에 대한 법률 결론이나 전문가 검토된 정답은 아니다.

보고서는 질문별 원문 검색 결과·보완 검색 결과·목표·적중 수와 임베딩 모델, 코퍼스 해시를 포함한다. 최종 버전부터 용어 규칙 파일 해시도 기록한다. 보고서와 키는 Git에 포함하지 않는다. 실행 중 코퍼스를 바꾸지 않도록 기존 로컬 운영 명령 잠금을 사용한다.

## 질문 구성과 근거

첫 10개는 수리비 지출, 보일러 고장, 곰팡이, 누수 수리비, 방 사용 불가, 보증금 미반환과 이사, 자동 연장 후 종료, 법률 용어를 직접 사용한 질문 3개다. 목표는 다음 공식 조문과 연결했다.

- 수선 의무·비용·사용 불가: [수집 버전 민법](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=284415&efYd=20260317)의 제623·626·627조.
- 보증금 미반환 후 이사·묵시적 갱신 후 종료: [수집 버전 주택임대차보호법](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=276291&efYd=20260102)의 제3조의3·제6조의2.

첫 결과 확인 후 규칙을 고정한 상태에서 천장 누수, 배관 수선비, 보증금 미반환과 이사, 묵시적 갱신 종료의 다른 표현 4개를 추가했다. 코드의 `holdout-` ID와 보고서의 `holdout` 구분은 이 추가 질문을 가리킨다. 이후 누수 표현 누락을 수정할 때 같은 질문을 재사용했으므로 **최종 결과는 독립 홀드아웃 평가가 아니다.**

## 측정 기록

2026-09-10 개발 DB의 기존 법령 3종·임대차 임베딩 121개를 대상으로 실행했다. 아래 수치는 질문 수가 아니라 선정한 목표 조문의 적중 횟수다.

| 단계 | 원문 검색 | 용어 보완 검색 | 의미 |
| --- | ---: | ---: | --- |
| 최초 질문 10개 | 4/11 | 11/11 | 개발 질문 비교 |
| 규칙 고정 후 추가 질문 4개 | 1/4 | 3/4 | 처음 본 표현 비교 |
| 위 14개 합계, 활용형 수정 전 | 5/15 | 14/15 | 천장 누수 질문 누락 |
| 활용형 수정 후 같은 14개 재검증 | 5/15 | 15/15 | 이미 본 질문의 회귀 평가 |

추가 질문 중 “천장에서 물이 샙니다”는 “물이 새”라는 기존 문자열 조건에 맞지 않았다. 해당 질문에 수선 관련 용어가 추가되는지 검사하는 테스트를 먼저 실패시킨 뒤 “물이 샙” 활용형을 추가했다. 정답 조문이나 결과 순위를 조건으로 삼지 않았다. 수정 후 목표 적중은 15/15로, 최초 수리비 질문의 제623·626조도 둘 다 포함됐다. 질문별 목표 전부 충족은 원문 5/14개, 보완 후 14/14개였다. 이는 모든 반환 조문이 적절하다거나 실제 서비스 정확도가 100%라는 뜻이 아니다.

로컬 실행 기록은 최초 `1789010462444`, 추가 표현 검증 `1789010502848`, 최종 재검증 `1789010625267` 디렉터리에 있다. 최종 보고서의 `completed=true`와 14개 행을 확인했다.

## 서버 반영 범위와 한계

`HousingSearchTerms`는 검색 관련 용어를 붙이는 작은 규칙 집합이다. 원래 질문을 삭제하거나 날짜·금액·법률 결론을 추가하지 않는다. 주택 맥락 표현이 없는 자동차 수리비·주식 질문은 그대로 둔다. 이는 완전한 주제 분류기가 아니며 단순 문자열 일치에 따른 오탐·누락이 가능하다. 부정문·이미 해결한 문제도 관련 용어가 붙을 수 있다. 그런 용어는 사용자 사실이 아니라 검색을 위한 힌트다.

실제 API는 같은 보완문을 임베딩과 단어 일치 검색 양쪽에 사용한다. 호출 횟수는 기존처럼 검색당 1회지만 추가 용어만큼 입력 토큰이 늘어난다. 원문 최대 1000자와 현재 추가 용어가 기존 6000 UTF-8 바이트 한도를 넘지 않는지 자동 테스트로 검사한다. HTTP 요청·응답 스키마는 그대로다.

이 평가는 작은 가상 질문군으로, 실제 사건 검색 정확도·불필요한 결과의 비율·사건 당시 법 적용을 보장하지 않는다. 현재 검색은 관련 없는 질문에도 가까운 후보를 반환할 수 있다. 동의어 누락, 복합 쟁점, 판례, 부칙과 경과규정, 검색 결과의 법률적 적용 여부는 별도 검증이 필요하다. 이 결과만으로 검색 후보를 확정 법률 답변으로 사용하지 않는다.
